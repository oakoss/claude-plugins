The commit gate reads github/gh-stack's `gh stack` commands instead of refusing every one as an unknown extension. Moving around a stack (`view`, `checkout`, `up`, `down`, `top`, `bottom`, `trunk`), `init`, `add` with no options and `unstack --local` run as they are. `rebase` and `sync` rewrite commits as `git rebase` does, so each runs as its own command and its replayed commits are not reported as unreviewed. An option written before the stack command is refused, since its value could hide which command runs. `push`, `sync` and `submit` push every active branch of the stack with `--force-with-lease`, so they need a request for a forced push; `submit` and `link` also open pull requests and are judged as one. `gh stack merge <number>` is judged by what it merges, read from GitHub's stacks API as gh-stack reads the number: every unmerged layer of that stack, or that pull request and every unmerged one below it. Each is judged as `gh pr merge` would judge it, the version pull request's release included, and a merge of several needs your message to name every one, to merge now or once ready (or a stop-before setting that merges without asking). A merge with no number, one run beside other commands or against another repository, and one GitHub cannot place are refused with what to do instead. `rebase --continue`, which commits a conflict's resolution, `add` with an option, `unstack`, `modify` and `switch` are refused with what to run instead.
